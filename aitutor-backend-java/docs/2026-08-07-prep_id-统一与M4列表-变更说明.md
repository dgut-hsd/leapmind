# 变更说明：prep_id 统一 + M4 备课列表支持

> 分支：`feature/ppt-template-management`
> 日期：2026-08-07
> 范围：`aitutor-backend-java` 后端

---

## 一、背景与目标

1. **M4 备课列表**：在既有接口 `GET /api/lesson-prep/contents` 上支持 M4 发布版 PPT 备课列表查询（类型筛选 + 新增字段）。
2. **prep_id 统一**：历史数据 `prep_id` 与 `id` 不一致、存在重复；且直插 SQL 的新增数据 `prep_id` 为 NULL，需要让 `prep_id` 恒等于 `id` 并保证唯一。
3. **兼容性要求**：不修改任何接口路径、不修改前端调用方式，只改插入逻辑 + 迁移历史数据。

---

## 二、数据库迁移（3 个新文件）

### V8 —— M4 列表新增列
`db/migration/V8__add_m4_lecture_columns.sql`

| 列名 | 类型 | 说明 |
|---|---|---|
| `type` | VARCHAR(20) DEFAULT 'ppt' | 内容类型（ppt/doc/text） |
| `subject` | VARCHAR(50) | 学科（math/chinese/english/...） |
| `grade` | VARCHAR(20) | 年级（grade_7/grade_8/...） |
| `knowledge_points` | JSON | 知识点列表 `[{id, name}]` |

### V9 —— 历史数据统一 + 唯一索引
`db/migration/V9__sync_prep_id_with_id.sql`

- `UPDATE teaching_contents SET prep_id = id WHERE prep_id IS NULL OR prep_id != id`：历史数据统一。
- 先 `DROP INDEX idx_prep_id`（V3 建表时创建的是**普通**索引），再 `ADD UNIQUE INDEX idx_prep_id (prep_id)`，保证唯一。

### ~~V10 —— 生成列方案已撤销~~（DB 层强制不可行，见下）

曾尝试将 `prep_id` 改为生成列 `AS (id) STORED`，但 MySQL 报 **ERROR 3109：Generated column cannot refer to auto-increment column**（`id` 是 AUTO_INCREMENT，生成列禁止引用自增列），启动即失败（Flyway 中止）。

实测验证过的替代手段也均不可行：
- **BEFORE INSERT 触发器**读 `NEW.id` 得到的是 0（自增值在触发器之后才分配）；
- **AFTER INSERT 触发器**更新同表被 MySQL 禁止（error 1442）；
- 去掉自增由触发器生成 id 会破坏 MyBatis-Plus 的 id 回填及所有依赖自增的业务，代价过大。

**结论**：`prep_id = id` 无法在 DB 层强制，改由 **Java 侧 `save()` 回填**保证（覆盖所有 API / 应用内脚本路径）。V10 文件与 Flyway 失败记录均已删除；直插 SQL 需显式写 `prep_id`（或留 NULL，唯一索引允许多个 NULL）。

## 三、Java 代码改动

### 1. 实体 `TeachingContent.java`
- 新增 4 个字段：`type`、`subject`、`grade`、`knowledgePoints`（对应 V8 列）。
- `prep_id` 保持普通列 `@TableField("prep_id")`（生成列方案不可行，回退）。

### 2. Service
- `TeachingContentService.listByUserId(userId, status, type)`：新增 `type` 参数，为空时不筛选（不传 type 返回所有类型，不影响既有调用）。
- `TeachingContentServiceImpl`：保留 `save()` 重写——插入前 `prepId` 置 NULL（避开唯一索引冲突），插入后回填 `prep_id = id`。这是 prep_id = id 的最终保障（DB 层无法强制）。

### 3. `TeachingContentController`（M4 列表 + 流式 SSE）
- `listContents`：透传 `type` 参数；`type=ppt`（M4）时列表 `pptStructure` 置空，保留详情接口的能力。
- `convertToVO`：从 `generated_content_json` 兼容解析 `subject / grade / knowledgePoints`（兼容 wrapper 与流式原始 syllabus 两种格式），解析异常时字段保持 null，不影响主流程；`slideCount` 从 `ppt_structure` 计算。
- 修复了此前文件中缺失的 `PythonApiClient` import 与字段（SSE 端点此前无法编译）。
- 流式 `persistStreamResult`：去掉 `.prepId(...)`，`saved` 事件与日志的 prepId 改用 `content.getId()`。

### 4. `LessonPrepController`（非流式 generate）
- builder 去掉 `.prepId((long) pythonResult.getPrepId())`。
- 响应 `prepId` 统一改为 `content.getId()`（= 库内 `prep_id`），接口路径、参数、调用方式不变。

## 四、返回值语义说明（需前端知悉）

接口返回的 `prepId` **值**有变化：

| 接口 | 改动前 | 改动后 |
|---|---|---|
| `POST /api/lesson-prep/generate` | Python 侧 prepId | `content.getId()`（= prep_id） |
| SSE `saved` 事件 | Python 侧 prepId / 时间戳 | `content.getId()`（= prep_id） |

路径、请求参数、调用方式均未改，仅返回值对齐新事实（prep_id = id），否则前端拿返回值查库会查不到。
